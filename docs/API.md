# Implemented API

Machine-readable baseline: [OpenAPI 3.1](openapi.json), generated by `pnpm api:generate` from `scripts/openapi.ts` and shared runtime validators. It documents current behavior, including differences from the companion contract. Planned endpoints are not presented as implemented.

Base path `/api/v1`. JSON bodies except photo upload. All mutations require an exact `Origin` matching APP_ORIGIN. Auth uses HttpOnly access/refresh cookies; tokens must not be stored in browser localStorage. Errors use `{error:{code,message,request_id}}`. Paginated discovery uses an opaque UUID cursor. This is an inventory of implemented endpoints, not the complete original API contract.

| Method       | Path                                     | Purpose                                                            |
| ------------ | ---------------------------------------- | ------------------------------------------------------------------ |
| GET          | /health, /config                         | Database readiness and public feature flags                        |
| POST         | /auth/register                           | Adult account registration; no client role grants                  |
| POST         | /auth/login, /auth/logout, /auth/refresh | Session lifecycle                                                  |
| POST         | /auth/verify, /auth/resend-verification  | Single-use email verification                                      |
| POST         | /auth/demo                               | Local demo shortcut; unavailable with DEMO_MODE=false              |
| GET, PATCH   | /me                                      | Own account and profile                                            |
| POST         | /me/photo                                | Multipart field `photo`; pending moderation                        |
| POST         | /me/creator                              | Add creator capability for verified email accounts                 |
| GET          | /people                                  | `q`, `city`, `role`, `min_age`, `max_age`, `cursor`                |
| POST         | /people/:id/like, /pass, /follow, /block | Profile interactions                                               |
| POST         | /people/reset-passes                     | Development baseline pass reset; premium policy pending            |
| GET          | /blocks                                  | Own blocked users                                                  |
| DELETE       | /blocks/:id                              | Unblock, without restoring the old match                           |
| POST         | /reports                                 | Submit a user report                                               |
| GET          | /conversations                           | Own active mutual matches                                          |
| GET, POST    | /conversations/:id/messages              | Read/send authorized text messages; send requires a UUID client_id |
| POST         | /conversations/:id/read, /unmatch        | Read state and unmatching                                          |
| GET          | /events                                  | Published upcoming events                                          |
| POST, DELETE | /events/:id/rsvp                         | Free RSVP or cancellation                                          |
| GET          | /admin/queue                             | Staff reports and photo queue                                      |
| POST         | /admin/photos/:id                        | Staff photo approval/rejection                                     |
| POST         | /admin/reports/:id                       | Staff resolution, optionally suspend target                        |

GET `/media/:file` is outside the API prefix but requires the same authentication and media ownership/visibility rules. Approved profile photos are visible to authorized signed-in viewers; pending photos are private to the uploader and staff.
